# Ultima IV (C64): reverse-engineering notes

Ultima IV: Quest of the Avatar, (c) 1985 Origin Systems, Inc. / Lord British. These are
notes on the original C64 game as it is on its four disks, independent of the cart. How
the cart replaces the disk access is in `docs/developer/u4.md`, and what Ultima IV
Remastered changes is in `docs/reversing-notes/u4-remastered.md`.

Addresses are runtime C64 addresses in the unit named. A "block" is a linear 256-byte
block of a disk, numbered from 0 at T1/S0, which is the game's own numbering. Findings
come from disassembly unless they are marked as inferred or as measured in VICE.

## The disks

| Disk | Role | Game's disk number (block 0 byte 0) | BAM disk ID |
|---|---|---|---|
| A | Program ("ULTIMA DISK") | 1 | `01` |
| B | Towne ("TOWN DISK") | **3** | `02` |
| C | Britannia ("BRITANNIA DISK") | **2** | `03` |
| D | Underworld ("DUNGEON DISK") | 4 | `04` |

- Disk A's directory holds one file, `ULTIMA` (PRG, 9 blocks, from T17/S0). Disks B, C and
  D have no directory. Their BAMs look plausible ("664 blocks free") but mean nothing:
  every byte on them is reached by block number.
- Disk A's image carries an error map. All 21 sectors of track 6 (blocks 105-125) are
  error 20, HEADER NOT FOUND. This is the copy protection (below).
- The four disks hold 4 x 683 = 2732 blocks but only **1579 distinct pages**. Code,
  music, templates and filler repeat across disks so that the game never needs a swap
  for them. Chunks `$56-$5A` (the music) are byte-identical on all four disks.

**Two numberings, two traps.** The game's disk numbers are not in letter order: 2 is
disk C and 3 is disk B. The BAM IDs are a different numbering that happens to overlap.
The authoritative one is block 0 byte 0.

## Boot chain

`ULTIMA` is loaded with `LOAD"*",8`, **without** secondary address 1. The KERNAL
therefore ignores the stored load address `$0800` and loads it to BASIC start, `$0801`.
Only that base lines up with its `SYS 2064` stub. Disassembled at `$0800`, everything is
one byte off and decodes as plausible garbage. (`da65` also counts the PRG header as code
unless it is stripped.)

```
$0810  LDA #$36 / STA $01     ; BASIC out: RAM at $A000-$BFFF
$0814  LDX #$C0 / TXS         ; the stack moved down
$0817  clear VIC/SID; $0839-$095A paints the credits title screen
$095B  copy $0974-$0F73 -> $A100-$A6FF   ; the resident kernel
$0971  JMP $A429
```

`$A429` (BOOT) loads the boot set and runs the title:

| Order | Command | Index | Result |
|---|---|---|---|
| 1 | `L` | record `$17` | the sound driver glue to `$AF20` |
| 2 | `L` | chunk `$4F` | SUBS, `$0800-$1FFF` |
| 3 | `L` | chunk `$4D` | `$9F00` |
| 4 | `L` | chunk `$41` | the tile bitmap, `$B000-$CFFF` |
| 5 | `L` | chunk `$4C` | tables and tile colours, `$E000-$E3FF` |
| 6 | `L` | chunk `$42` | the font, `$E400-$E7FF` |
| 7 | `R` | chunk `$50` | the title and menu, `$6000-$72FF`, then `JMP $6000` |

## The resident kernel, `$A100-$A6FF`

The kernel is the only code that touches the drive. It uses plain KERNAL calls
(`OPEN`/`CHKIN`/`CHRIN`/`CHROUT`/`CLOSE`) on a direct-access channel. There is no
fastloader and no drive code. It has 29 KERNAL call sites, all inside this block.

**Jump table** (the whole API):

| Entry | Target | Purpose |
|---|---|---|
| `$A100` | `$A12E` | command dispatch: `R` (`$D2`) load and run, `L` (`$CC`) load, `S` (`$D3`) save; X = index |
| `$A103` | `$A45E` | LOADBLK, the block transfer |
| `$A106` | `$A429` | boot / restart |
| `$A109` | `$A118` | SID volume toggle (`$A126` mirrors `$D418`) |
| `$A10C` | `$A68F` | KERNAL in (`$01 = $36`) |
| `$A10F` | `$A674` | KERNAL out (`$01 = $35`) |
| `$A112` | `$A127` | clear the keyboard buffer |
| `$A115` | `$A6AC` | the IRQ vector hook; `$A116` is the vector modules chain into |

**Parameter block `$A000-$A005`**: `$A000` op (1 read, 2 write), `$A001` block count,
`$A002/3` address, `$A004/5` linear block number.

**Key routines**

| Address | Role |
|---|---|
| `$A45E` | LOADBLK: saves SP at `$A508`, KERNAL in, opens the channels, runs the transfer loop |
| `$A48F` | linear block to track/sector, by repeated subtraction against `$A4E4` |
| `$A4E4` | the 1541 geometry, 36 entries: `$FF`, then 21 x `$15`, 7 x `$13`, 6 x `$12`, 5 x `$11` |
| `$A52F` | builds and sends `U1:2 0 t s`. The `1` at `$A5B5` is self-modified from the op byte (`LDA $A514 / CLC / ADC #$B0 / STA $A5B5`), so a write is `U2` |
| `$A543` / `$A559` | 256 x `CHRIN` into `($0E),Y` / 256 x `CHROUT` from it |
| `$A5BD` | `B-P:2 0` before a write |
| `$A5E3` | `OPEN 15,8,15` and `OPEN 2,8,2,"#"` |
| `$A627` | reads the error channel: anything but `00` fails |
| `$A669` | `CLOSE 2`, `CLOSE 15` |
| `$A1C0` | on a failure: `INC $D020` and retry, forever |

The command strings are stored with bit 7 set and sent with `AND #$7F`: `$A5B4` is
`U1:2 0 `, `$A5D9` is `B-P:2 0 `, and `$A624` is `#`. The kernel's dead text at
`$A6DD-$A6FF` is padding.

### Chunks and records

The dispatcher splits indices at `$40` (`CPX #$40` at `$A167`). Six tables tile the
kernel with no gap, which pins their sizes:

```
$A218 + 29*1 -> $A235   record lengths
$A235 + 29*2 -> $A26F   record addresses
$A26F + 29*2 -> $A2A9   record block numbers
$A2A9 + 96*1 -> $A309   chunk block counts
$A309 + 96*1 -> $A369   chunk destination pages
$A369 + 96*2 -> $A429   chunk start blocks (BOOT follows)
```

So there are 29 record slots (`$00-$1C`, 28 live) and **96 chunk slots (`$40-$9F`, 81
live)**. Entries of `$FF`/`$FFFF` are unused. Assuming 64 chunks drops 19 of them,
including the `$E800` overlays and the `$0400` screen loader. A chunk is `count` whole
blocks from `start` to `page << 8`. A record is always one block, staged through `$9E00`
and copied to its address for `length` bytes. **The same index means different content
on different disks**: that is how Towne, Britannia and Underworld swap their data.

**Chunks** (index, destination, blocks, first block). Where the disks differ, the start

What the chunks are, as far as these notes and the Remastered analysis identify them:
`$40` an alternative `$0800` program (it holds a copy of the boot's banking code), `$41`
the tile bitmap, `$42` the font, `$43` the title picture's bitmap, `$45-$4B` the
character creation pictures (`$4B` the abacus), `$4C` tables and the tile colours, `$4F`
SUBS (the resident subroutines), `$50` the title and main menu, `$51` character
creation, `$52` the virtue cards, `$53`/`$54` the save templates, `$55` the title music
player, `$56-$5A` the songs, `$5B` game main, `$5C-$6C` the per-disk maps (town maps on
B), `$6D-$76` the shops, `$77` Peer, `$78` the talk overlay, `$79` Search, `$7A` Use,
`$7B` Mix, `$7E`/`$7F`/`$80` the save slots, `$82` a shrine, `$85` Camp, `$87`/`$88` Lord
British and his help, `$89` the resurrection, `$8C-$93` the `$E800` overlays, `$95` the
dungeon view, `$9A`/`$9B` the ending, `$9E` the title's colours (screen RAM), `$9F` the
cards' colours.

**Records**: `$00` block 0, 1 byte to `$0050` (the disk number); `$01-$16` blocks
584-605, 192 bytes each to `$AE40`; `$17` block 252, 224 bytes to `$AF20` (the sound
driver glue, loaded at boot); `$18` block 256, 32 bytes to `$0010` (the zero-page
template of a new game); `$19` block 352, 128 bytes to `$8800`; `$1A` block 275, 32 bytes
to `$0010` (the zero-page save slot); `$1C` block 281, 128 bytes to `$AE80`.

**Double-mapped blocks.** Blocks 271-275 are the save slots (`$7E`, `$7F`, `$80`, `$1A`)
and also fall inside map chunks `$4B` (257-285) and `$5F` (272-276). Which applies depends
on the disk: on C they are save slots, on the others map data. A block can have more
than one owner.

### Disk swapping and the identity check

On a read error the kernel flashes the border and retries forever (`$A1C0`). It never
looks at the error, so it cannot tell "wrong disk" from "no disk".

**The game does check which disk is in the drive**, in the disk-swap overlay, not in the
kernel. A scan of the kernel alone finds nothing; the check is in an overlay. There are
four copies, one per load address: chunks `$4F` (`$1914`), `$50` (`$6E79`), `$51`
(`$692D`) and `$9A` (`$8879`). On disk A, three sites hold them, because `$50` and `$9A`
share a block. In the `$51` copy:

| Address | Role |
|---|---|
| `$692D` | entry: `STA $5E`, the wanted disk number in A |
| `$692F` | the prompt loop |
| `$69C7`, `$6A17`, `$69E4` | `PLEASE PLACE THE`, the disk's name by `$5E`, `INTO DEVICE <n> AND PRESS [F1]` |
| `$69FC` | after the key: `L` record `$00` (one byte to `$0050`), `STA $51,X` (the cache "disk now in drive X"), `CMP $5E`, and on a mismatch back up two rows and prompt again |

`$51 + $5F` is the persistent "disk in drive N" cache. `$5E` is the request.

## Banking and interrupts

The game plays with **`$01 = $35`**: KERNAL out, RAM at `$E000-$FFFF`, and its own
vectors at `$FFFA`/`$FFFE`. It switches to `$36` only for a disk call or an interrupt.
`$A674` (BANKOUT) does `SEI`, sets IRQ -> `$A696` and NMI -> `$A6BB` in RAM, `$01 = $35`,
`CLI`. `$A68F` (BANKIN) sets `$36`. The trampolines `$A696` -> `$A6AC` and `$A6BB` ->
`$A6D5` switch to `$36`, `JMP ($FFFE)` / `JMP ($FFFA)` into the ROM, and write `$35` on
the way out.

| Address | Value | Meaning |
|---|---|---|
| `$0810` | `$36` | boot: BASIC out |
| `$A68B` | `$35` | play |
| `$A692` | `$36` | around every disk access |
| `$A6AE` / `$A6B5` | `$36` / `$35` | IRQ trampoline |
| `$A6D0` / `$A6D7` | `$36` / `$35` | NMI trampoline |

**The banking code exists three times**: in the kernel, and relocated copies in chunk
`$40` (`$0C04-$0C61`) and chunk `$6C` (`$8E04-$8E61`). Other `$00`/`$01` hits from an
opcode scan are data. A scan of every chunk on the four disks and the kernel finds every
write to `$01` is `$35` or `$36` (one hit at `$A3CB` is a word table). The game never
banks I/O out, so **the RAM under I/O, `$D000-$DFFF`, is unreachable to it**, and
nothing loads there.

The trampolines write `$01` whole, which also sets the cassette lines (bits 3-5). The
game's IRQs end in the KERNAL's handler through `$0314` = `$EA31`, cassette code
included. **Only character creation (chunk `$51`) stores to `$0314`**, for its raster
split. That is from a scan of all four disks.

**CIA 2**: nothing on the four disks touches it but `$DD00` (a scan for absolute `$DD0x`
operands found one hit, in graphics).

Static scans (all four disks, chunks and records, absolute operands; they do not see
`(zp),Y`) and VICE memmaps give these results:

- **`$A006-$A0FF`**: nothing loads there, and every operand hit is graphics or text. A
  VICE memmap of play saw no access.
- **`$F200-$F3FF`**: the last two pages of chunk `$55`, filler on disk A, with only data
  hits statically. But **a VICE memmap of play (Britannia, a town, a dungeon with a
  fight and a peer) saw 209 reads in `$F302-$F3FD` by the original game**. Treat both
  pages as used.
- **`$FF00-$FFF9`**: nothing loads there. Every hit is a `JSR $FFxx` (run with the ROM
  in) or data.
- **`$9D00-$9DFF`**: nothing loads there. The only absolute operands are game main's
  `JSR $9DAC`/`$9DAE` (play time) and data. That is static evidence only.
- **`$86EF-$87FF`** (chunk `$5B`): residue. `$86EF-$87EE` is a stale copy of
  `$61EF-$62EE`, `$87EF-$87FF` an older version, and `$8800-$8FFF` `$01` filler. The
  last live routine ends at `$86EE`. Only chunks `$44` and `$51` load over it, and both
  reload `$5B` afterwards.
- **`$71E0-$72FF`** (chunk `$50`) and **`$96E6-$97F7`** (chunk `$51`) are residue
  (source text), with no references found.
- **`$0334-$03FF`**, `$02A7-$0313`: no plausible references. Only chunk `$51` touches page
  3, and only `$0314/$0315`.

A watchpoint only covers what the session did. Exercise every mode before calling RAM
free.

## Copy protection

Chunk `$50` at `$6C6E` (run first by the boot) reads block 115 (track 6, sector 10) into
`$9E00` through `$A103`, and **requires the read to fail**:

```
$6C8C  JSR $A103
$6C8F  BCS $6C96          ; read failed: the original disk, go on
$6C91  PLA / PLA          ; read succeeded: a copy
$6C93  JMP $67A2          ;   -> bail out
$6C96  LDA #$00 / STA $D020 / RTS
```

On an original, track 6 is unformatted. A copy that reads it bails out.

## The overworld block reader

SUBS' `$0A7F` (chunk `$4F`) bypasses the tables. It computes `(($60 << 4) | $61) + 1`,
with both nibbles masked to 0-15, so blocks 1-256 of the current disk, and reads the
four 256-byte map chunks around the party into `$E800-$EBFF` through `$A103`. Its op
byte `$62` is only ever set to 1 on any of the four disks, so it never writes. Chunks
`$40`, `$6C` and `$89` contain relocated copies of the routine, but they `JSR $0A7F`
rather than run their own.

## Saves

Saves go only to **disk C**, from chunk `$5B`'s four `S` calls:

| Unit | Block | Loads to | What | Template on disk A |
|---|---|---|---|---|
| chunk `$7E` | 271 | `$AC00` | the temporary map: Britannia's object table while the party is in a location | chunk `$53` (block 253) |
| chunk `$7F` | 272 | `$AC00` | the object table | chunk `$53` |
| chunk `$80` | 273-274 | `$AA00-$ABFF` | the roster and inventory | chunk `$54` (254-255) |
| record `$1A` | 275 | `$0010-$002F` | game state | record `$18` (256) |

- Call sites: `S $7E` at `$51F2` (from `$51F6`, entering a towne, castle or keep, and
  from `$507A`, entering a dungeon), `S $7F` at `$583F`, `S $80` at `$5844`, `S $1A` at
  `$5849`. `$7E` is loaded at `$462F` (leaving). Restore: `$4050` (`L $7F`, `L $80`).
- Character creation loads the templates (chunk `$51`, `$6641-$664F`: `L $18`, `L $53`,
  `L $54`), and `$66B3` sets `$1F` = 1.
- **Quit & save only works on the surface**: `$582A LDA $1A / BEQ / JMP $4178` ("NOT
  HERE!"). So `$7E` is session scratch that happens to live on disk (inferred from its
  two sites). Loading (`$405C`) forces `$1D = $74 = 0`, `$1A = 0`, `$1B = 1`: a game
  always resumes on the surface, and not flying.
- **The active-game flag** is `$1F`. At `$4026`: if it is clear, `L $1A`; if it is still
  clear, print `NO ACTIVE GAME!` (`$4038`) and `JMP $404D`, which jumps to itself. Pressing
  J at the title with no saved game hangs the game.

**Roster format** (`$AA00`, 8 slots of 32 bytes): name, NUL-terminated (the rest of the
field is residue); +16 sex (`$5C`/`$7B`); +17 class 0-7 (inferred from the template's
order); +18 status `$C7` G, `$D0` P, `$D3` S, `$C4` D (set at `$7DC1`, `$84D8`, `$6247`);
+19-21 STR/DEX/INT; +`$18/$19` hit points and +`$1A/$1B` their maximum, BCD, high byte
first (`$84B0`, `$8501`). `$AB00` starts with 8 bytes of `$50`, then `$02`. Bytes 17 and 18
together are a reliable signature for finding a roster on an image. Food is BCD at
`$AB10-$AB12`.

**The pristine state.** On a factory Britannia disk, blocks 271 and 272 are all zero
(equal to block 253 on disk A). 273-274 are byte-identical to disk A 254-255, the eight
canonical companions in a fixed order. 275 equals disk A 256 except byte `$0F` (`$1F`),
which is 0 instead of 1. A scan of all four disks for the roster signature finds only the
template and that slot, both canonical. A factory disk set boots to `NO ACTIVE GAME!`.
Disk A 253-256 is identical in every matching disk A dump examined, so a played
Britannia disk can be rebuilt from disk A.

## The two editions of disk D

Disk D differs between dumps in one tile. Block 76 (T4/S13) is a dungeon room page.
Room pages are `16 * dungeon + room`, and the block is the page + 1, so this is
Covetous's room 11, on level 7. Byte `$BE` is the room map's tile at (7, 5). The Ultima
Trilogy's disk D has floor (`$16`) there, and every dump of the 1986 release examined (ten)
has a wall (`$7F`). The room is five corridors of floor between walls, mirror-symmetric
except for that square. A monster (`$D4`, slot 12) stands on it, inside the wall in the
1986 dumps. The room's one trigger, at (1, 5), opens (10, 5), the east end of that
corridor, which the wall cuts off from the room. So the Trilogy's disk carries a one-tile
fix. The game never writes disk D.

**Dungeon room page layout**: triggers `$00-$0F` (four bytes each: the tile to put, the
trigger's position, two target positions); monsters at `$10`/`$20`/`$30`; the party's
start x/y for each entry direction at N `$40/$48`, E `$50/$58`, S `$60/$68`, W `$70/$78`;
the 11 x 11 map at `$80`. Some rooms have no start positions for a direction, which in the
original puts the party at (0, 0), a wall corner: Destard's rooms `$2C`/`$2E` (east and
west), Hythloth's `$67` (all), and `$69` (west). See the Remastered notes.

## Text and conversations

- **The font has lower case.** `console_out` (`$0824` -> `$102A`) masks bit 7 and draws
  that glyph. The font (chunk `$42`, `$E400`, 128 glyphs) has real lower-case letters, and
  the game prints mixed case in a few places ("Pass", "Zzzzz", "Your interest:", "Return
  to the view", "Journey onward", the Codex questions). Game text is ASCII with bit 7 set,
  and `$8D` is a line break. Strings are printed inline after `JSR $0821` (and `$081E`
  at a position).
- **Talk pages**: disk B blocks 1-256, one conversation each, loaded to `$AD00` by the
  talk overlay (chunk `$78`). Byte 0 is `$00`, then ten NUL-terminated strings in
  `$01-$EF` (name, pronoun, description, job, health, response 1, response 2, question,
  yes, no). Keyword 1 is at `$F0` and keyword 2 at `$F6` (six characters, four compared).
  `$FC` is the question trigger: 3 job, 4 health, 5 keyword 1, 6 keyword 2, 0 never.
  `$FD` is a second trigger that prints "SPECIAL!" (0 on all 256 pages), `$FE` the
  humility flag, `$FF` the turns-away value (BCD). There is no word wrap: every line is
  pre-broken.
- Typed input arrives as capitals (`$C1-$DA` whatever Shift says) and is compared with an
  upper-case keyword table (`BYE NAME LOOK JOB HEAL`, keyword 1, keyword 2, `JOIN GIVE`).
  The matcher scans from index 9 down, so a keyword 2 beginning `HEAL` shadows HEALTH.
- **Town maps**: the map chunk's last `$100` bytes are its NPC table. `$4E0-$4FF` is the
  conversation number for each NPC. Talk page = town x 16 + conversation - 1 (checked by
  content).
- Conversations that no map references: Thevel's (Britain's NPC 13 points at Joe's,
  conversation 7, instead of 6), the gate guard's in Serpent's Hold (NPCs 28 and 29 use
  conversation 1, Sentri's), and Isaac's in Skara Brae (not investigated; he may be
  placed by code). Castle Britannia's upper-floor conversations are covered by chunk
  `$6C`.

## Bugs in the original

Found by the Ultima IV Remastered author and checked in disassembly here. See the
Remastered notes for the fixes.

- **Stack leaks.** The main loop `$407B` and every command end in JMPs, so the depth is
  constant, but three paths leave a return address: being attacked (`$628A JSR $667C` ...
  `$670A PLA/PLA` drops one, then `JMP $4731`: `$628C` stays), the bridge trolls
  (`$407E JSR $62B0` -> `JMP $6EA3`: `$4080` stays), and the party dead (`JSR $83A8` ->
  `JMP $83C7` ... `JMP $621E`). Nothing ever resets S: the only `LDX #imm / TXS` on any
  disk is the boot's and two relocated copies of it. The stack wraps silently. Inferred:
  once it has wrapped, the ROM IRQ entry's BRK test (`$FF48`: `TSX / LDA $0104,X / AND
  #$10`) can read a stray bit 4 and send an ordinary IRQ to BASIC's warm start, `READY.`
  The main menu's and creation's `R` by JSR (`$6966`, `$6A27`, `$640B`) and the ending's
  throw-out also leak.
- **Character creation hangs at random.** Both IRQ-restore paths (`$67F5`, `$681E`) put
  the KERNAL vector back and `CLI` *before* disabling the raster IRQ in `$D01A` and
  acknowledging `$D019`. A raster IRQ pending at that moment loops forever.
- **Shrine, 0 cycles** (chunk `$82`, `$8907`): `JSR get_number / CMP #$04 / BCS / STA /
  STA / BNE go`. STA sets no flags, so BNE tests the Z of `CMP #$04`, which is clear for
  0-3. An answer of 0 meditates with a counter of 0, which the first `DEC` makes 255.
- **Shrine hints** (`$8C00`): the table of messages per cycle is `$18,0,0,0...`, so 1, 2
  and 3 cycles all show a virtue's first hint. The second and third hints (among them the
  Abyss ritual's order) are on the disk but never shown.
- **DEL** is compared with `$88`, the Apple II's backspace, in number entry (SUBS
  `$12F3`/`$130A`) and in Use in dungeons (`$7A` on D, `$8B08`). The C64's DEL arrives as
  `$94`.
- **B on a dungeon ladder** boards a frigate: tiles `$10-$13` are ships on the surface and
  ladders underground (`$47B0 JSR $480B`).
- **Attacking static NPCs**: the attacked object's tile becomes the combat monster
  (`$4733`), so the ankh, lords, the water in Castle Britannia and camp fires make
  glitching foes. Chests can be attacked (`$46E1`).
- **Resurrection music**: `$83C7` resumes the previous area's tune at Lord British's
  castle.
- **Typed-ahead keys are lost.** SUBS `$157E` takes `$0277`, the first queued key, and
  then empties the KERNAL queue (`$159D JSR $15A1`).
- Typos: `WH0-` with a zero (`$49DA`), `-GOLD!`, `THE ALTER ROOM`, and on D `THE ALTER` /
  `THYNE EYES`.

Found by Sean Gugler, whose continuation of Ultima IV Remastered (2.3.0-2.4.1,
github.com/sean-gugler/u4remastered) fixes them, and checked in disassembly here. The
command level's stack is `$BE` (measured in VICE at the main loop's key read `$408F`, at
`cmd_done` `$621E` and at combat's command read `$70EB`; the boot set `$C0`).

- **More stack leaks.** A moongate (`$8676`) is reached by JMP from a step's subroutine
  (`$448D` and its siblings `JMP $8676` with the tile; the direction commands JSR them,
  twice at a gallop) and leaves by `JMP $621E` (`$86CA`) or into a shrine (`JMP $5183`,
  `$8698`): two bytes a jump. Combat's Ztats (`$7CEA JSR $5CC8`) enters the Ztats command,
  which ends in `JMP $621E`. Z-down on the lowest level (`$4DFC JSR $4EB9`, the spell's
  failure, which ends in a JMP). The other way round, "ALL MUST USE THE SAME EXIT!"
  (`$7918 PLA / PLA`) pops two bytes the main loop never pushed: combat's move (`$7838`)
  is entered by JMP. And the party dead is reached from one to four calls deep: a sinking
  ship through a whirlpool, a twister, a pirate's cannon or a red missile (the fork's
  list), or the turn's end -- so dropping one return address there (Remastered's fix) is not enough.
- **The inn's morning** (chunk `$73`, B, `$8A6E`): a member asleep (`'S'`) wakes with
  status `'A'`, which nothing else knows: not alive (`$7DAF` wants `G`, `S` or `P`), not
  dead, out of every fight, curable only by Lord British.
- **A non-monster's strength** (`$7DA9`): `(tile & $1F) + $24` indexes the strength table
  without halving for the two animation frames each such foe has; from a shepherd on it
  reads past the table.
- **Ztats, the 3-part key** (`$60AF BEQ`): with the bell or book but no candle the branch
  past "CANDL" lands among the key's letters.
- **Serpent's Hold's healer** (record `$19`, block 352, the shopkeepers' rows, +`$1D`):
  `$0C` where the map has the healer at row `$12` -- "Funny, no response."
- **The skull destroyed** (chunk `$7A`, C, `$8ADA`): `LDY #$6A` where the loop's `LDY $6A`
  was meant, so the +10 for each virtue goes eight times to index `$6A` instead.
- **The last gold piece given** (talk code, chunk `$78`, `$8CD5`): Honor (5) gains, where
  the shrine of Sacrifice's first hint asks it for Sacrifice (4).
- **The healer's spell flash** (chunk `$72`, `$8E7D`): the bitmap line's address takes the
  low byte table `$E008` twice, so `$4048-$59F7` (game main) is inverted and put back,
  the view never; and its row is `$B8` bytes, one column more than the view.
- **Hawkwind's cooldown** (chunk `$76`, `$8A02`): `LDA $2F / CMP $29`, where the shrine,
  which shares `last_meditated` `$29`, compares `$2E`.
- **Search's reagent cooldown** (chunk `$79`, C): "YOU FIND..." (`$8841`) sets `$2A` for
  every find, the bell and the rest too.
- **The shrine** (`$895A`) reads `BIT $C010`, the Apple II's keyboard strobe, to drop the
  keys typed while meditating; on a C64 that reads RAM.
- **The skull's shake in Britannia** (`$8BCC`, `$8BFB`): `BIT $A109` where the sound's
  `JSR` was meant (the towns' and the Underworld's own shakes JSR).
- **Katrina's refusal** (talk code `$8D5F`): the humility reason has no RTS and runs on
  into the experience reason: "HUMBLEEXPERIENCED".
- **Four humility questions without the flag** (`$FE` = 0): Browning's "Hast thou never
  lied?", Aristotle's, Santayana's and Slysam's are asked as boasts, as the flagged ones
  are (Sir Hrothgar, Flamis, Estro, Diane, Slim, Silver John). An inference about intent,
  the fork's.
- **Bridge trolls while flying** (`$62B0`): the trolls' test comes before the "flying: no
  tile effects" test at `$62EA`.
- **Attacking a townsperson** costs three virtues (`$4720`-`$472E`) and the status is not
  drawn again; **the chest a townsperson drops** keeps their conversation (`$ACE0,X`,
  `$767B`); **an east-facing horse** flickers in combat.
- **X-it in a town** (`$5C36`): the transport's object slot is searched from 31 down to 8
  -- below 8 are Britannia's monsters, in a town people -- and with none free a random one
  of 16-31 is taken, someone vanishing. Lycaeum, Empath Abbey, Serpent's Hold and others
  start with slots 8-31 full. Board (`$4827`) looks only down to 8 too.
- **Dungeon Wrong** (chunk `$8F`, D): level 3's ladder down at (7, 4) meets a chest on
  level 4, whose ladder up is at (7, 3); level 8's ladder up at (4, 3) has no ladder down
  on level 7. A scan of all eight dungeons found one more (not the fork's): **Covetous
  level 6 at (3, 3)** is a ladder up and down, the foot of a stack from level 4, over
  plain corridor on level 7 (the cart adds the ladder up there). The Abyss's
  altars (`$B0`) lead down without a ladder below, by design.

## Music

The sound driver glue (record `$17`, `$AF20`): `JSR $AF20` with A = 0 ends the song and
waits for the player to go idle. A = 1 restarts song 1 from the start, but only if
nothing plays (`LDA $04 / BNE`). A >= `$80` selects a song, loads it to `$F400` through
`$A100` and starts it (`$C3` is `C`, chunk `$59`, the castle music). Game main has 23
`LDA #$00 / JSR $AF20` stops. Six of them (Descend `$4F94`, Klimb `$55FC`, Mix `$56B5`,
Quit & save `$5831`, Search `$59B7`, Use `$5AFF`) come before a load and are followed by
`LDA #$01 / JSR $AF20`, so the tune starts over. The player (chunk `$55` at `$EC00`, init
`$EC1F`) hooks its IRQ handler `$EC89` into `$A116` and keeps the previous one at `$ECC2`.
The handler writes the SID and CIA 1 (`$DC04/$DC05`, `$DC0D`) before the kernel banks
anything. Its zero page is `$02-$07`, `$2F-$3B` and `$4D` (a walk of the player's code from
its entries and its IRQ handler).

## Time spent in a step

Measured in VICE (PAL, key accepted at `$4092` to the next key read at `$408F`, Britain,
east along row 15 from the entrance, mean of 10 free steps): **321,690 cycles (0.327 s)**.
The monitor's profiler splits a free step like this:

- the view `$0C0B`, 52%: the cells' blit 22%, line of sight 13%, the buffer 4%;
- the text window's scroll `$160E` and character drawing, about 30% (a step prints a line
  and scrolls twice);
- creature movement `$667C`/`$7E1D`, 12% (the 16-byte additive random generator `$15C4` is
  called about 95 times a step);
- the music's interrupt, 5%.

Combat, dungeons and the overworld (`$0C72`) were not profiled.

- **The view buffer** (`$0C0B-$0C71`) fills the 11 x 11 buffer at `$AE80` from the 32 x 32
  town map at `$E800`, working out a map pointer for every cell (about 98 cycles). A cell
  outside the map is tile `$04`.
- **Line of sight** (`$0D65-$0E6B`): `$AE00` gets the visible tiles and `$7E` elsewhere. In
  pass 1, a cell is seen if a walk toward the party (both coordinates a step nearer 5
  until one is there) reaches the centre, 60, before an opaque tile (`$06 $08 $49 $7E
  $7F`). That is 408 steps of 76 cycles. In pass 2, a cell not yet seen is seen if a
  walk along the longer distance only (both when equal) reaches the centre.
- **The text scroll** (`$160E`) moves rows 13-23 of the text window (columns 24-39: 128
  bitmap and 16 screen bytes a row) with patched `LDA/STA abs,Y` loops (about 15 cycles
  a byte). It clears row 23 by printing 16 spaces through `$1687` (about 340 cycles
  each), 30,104 cycles in all.
- **A blocked step** costs about 480k cycles. `$41DE` prints "BLOCKED!" (a third scroll)
  and plays sound effect 1 through `$0854` -> `$19E5`: at `$1A27`, 50 rounds of
  `PHA/PLA/DEX/BNE` with X = 0, each ending in `JSR $A109`, which flips `$D418` between
  0 and `$0F`. That is a 160 Hz square wave made by the CPU, about 155 ms, and the game
  waits for it. `LDY #$32` at `$1A27` is its length. The walking click (effect 0) plays
  before the move is checked.
- **Tiles are animated by rewriting the shared tile bitmap**, not by choosing a frame at
  draw time: `$1426` rolls the pixel rows of tiles `$00-$02` and `$4C` (water), `$14A9`
  fills `$44` and `$4A` with random bytes, and `$1504` swaps byte pairs of tiles `$0A`,
  `$0B`, `$0E`, `$10` and `$12` (flags). All three run from the end of `$0F90` on every
  view draw, whether such a tile is in view or not (about 6% of a step). Only creature
  frames are chosen at draw time (`$0F90`: `$AC00` from `$AC60` at random).

## The title and menu (chunk `$50`)

`$6031` runs the logo (about 20 s of waits). `$676C-$67A1` sets up (`$1B`, `$53` = 0, `$51`,
`$52` = 1, `$4D` = `$FF`, the view's tables), loads the title music (`L $55`), and inits
and starts it. `$67A2` shows the animated view until a key, then the menu. The menu's J
(Journey onward) is `$6954`. The menu prints a "Number of drives" line (`$680F`), and N
leads to the drives prompt at `$6E38`. The title's view (`$6B83`) is a second copy of the
renderer (19 x 5 tiles at screen row 13). The dissolve (`$6525`) first copies a picture
(bitmap chunk `$43`, colours `$9E`) whose rows 13-22 are that view pre-rendered.

## Graphics format

The screen is a hires bitmap at `$2000` with screen RAM at `$0400` (`fg << 4 | bg` per 8 x 8
cell). A tile is 16 x 16: the upper half (two cells, 16 bytes) at `$B000 + 16 t`, the lower
half at `$C000 + 16 t` (`gettileaddr` `$148B`). In the original, a tile has one colour byte
(`tile_color`, `$E1B0`) written to all four cells, always on black. Its only readers are
the two renderers (SUBS `$0EBD`, chunk `$50` `$6BD4`). The bitmap row table is at
`$E000/$E0C0` (line n at `$2000 + 320 * (n / 8) + n % 8`) and the screen row table at
`$E180/$E198`.
