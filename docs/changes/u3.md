# Ultima III: Exodus on the cart -- what is different

Ultima III: Exodus is (c) Origin Systems / Lord British. The cart runs the original C64
game. Its disk access is replaced by flash reads and writes, and a few changes are added.
Several of those changes come from **Ultima III Gold**, a fan version of the C64 game
("cracked, trained and enhanced by MagerValp, released at BFP 2007, music by Zabutom",
as its scroll text says). Each one is marked below. Unless a change is listed here, the
game plays as the original does.

## The disks you need

The build reads three disk images that you supply. It finds them by content, under any
file name:

| Disk | What the build takes from it |
|---|---|
| Ultima III, side A (program) | the game's program files, the intro, the DOS module and the file catalog |
| Ultima III, side B (Player Master / Scenario disk) | the world data: maps, monsters, conversations, and the map of Sosaria |
| Ultima III Gold | the code of the Gold changes listed below |

**Side B may be played, and may be either edition's**: the Ultima Trilogy's "PLAYER
MASTER" or the 1984 "ULTIMA III-SCEN.", whose contents are the same. The game keeps the map of Sosaria (`SOSA`) on that disk.
It writes the map back every time it saves and never resets it, and no clean copy of it
exists anywhere else on the disks. The cart's fresh game, which is also what the page's
Reset returns to, has to start from an unplayed map. But the disk records what play puts
on the map: the monsters, the chests they leave, parked horses and frigates, the
whirlpool and the moon gate. The build takes them off again and checks that the result
is the unplayed map, byte for byte. A side B whose map was changed in some other way
(by Ultima III Gold's trainer keys, say) is refused, and `make disks` says why. The saved
game on a played disk is not lost: the build can import it into the cart as a saved game
(`make import`), on top of the clean base.
The other save units (roster, party, players, monster table) are generated by the build,
not copied from your disk.

**The Ultima III Gold disk is yours to supply too.** None of its data is shipped. The
build unpacks it on the PC, running Gold's own unpack code in a 6502 simulator. It takes
only the code and data of the changes listed below and checks that nothing else of Gold's
comes along. The tile and font data in Gold's layout are computed from your original
disks and compared with Gold's. Gold's save files (the map, the monsters, the party) are
not used at all, so a Gold disk that has been played works as well as a fresh one.

## No disks, no waiting

- **No disk prompts.** "INSERT SCENARIO DISK" is gone, and so is every other disk access.
- **Faster loads.** The original loads through the stock KERNAL at about 400 bytes per
  second. The cart loads at about 8.5 KB/s with the screen on. Most units are stored
  compressed, and the compressed ones still load more than ten times faster than from
  disk.
- **The copy protection check is gone.** On an original disk, the program checks at
  start-up that a damaged track cannot be read. On the cart that check is removed, so it
  passes as it does on an original disk.
- **The disk duplicator is not reachable.** In the original, pressing C during the intro
  started `COPY`, the Player Master copier. There is no drive to copy to, so on the cart
  C ends the intro like any other key.
- **The credits screen.** While it loads, the original boot program shows a title screen
  of credits (ORIGIN SYSTEMS ... MUSIC COMPOSED BY KENNETH W. ARNOLD). The cart shows the
  same screen for about four seconds when the game is launched. A key ends it early, and
  Journey Onward skips it.

## Saving

- **Only Q saves to the cart** (from Ultima III Gold, "revamped save system"). In the
  original, entering a town, castle or dungeon, coming back to Sosaria, the whirlpool to
  Ambrosia and every character's death all wrote the game to disk. Gold, and the cart,
  keep that state in memory instead, and only **Q** ("Quit & save", on the surface)
  writes the saved game. What this means for you:
  - anything since your last Q is lost when you switch off;
  - a death is not final: switch off (or relaunch the game) and your last Q save is back.
- **Character creation and forming a party** write the roster as the original does.
- **A save survives a power cut.** Each part of the saved game is written twice: first to
  a spare area, then over the old save. If the power fails during a save, you get either
  the old save or the new one, complete. If the power went while the old save was being
  overwritten, the cart finishes the job the next time it is switched on, before anything
  else starts.

## Faster screen (from Ultima III Gold)

Gold's rewrite of the tile plotting is on the cart: the tiles, the font and the animation
frames are stored in the C64's bitmap order, and Gold's routines copy a whole tile or
character at once. Measured on the original code against Gold's, a redraw of the map view
is about 1.9 times faster and text about 2.3 times faster. The map view redraws all the
time while the game waits for a key, so the game also notices a key sooner. The title
menu's map view uses Gold's routine too. What you see is identical to the original.

## Faster steps

A move's footstep sounds as it did: two clicks on foot, three on a horse, about as far
apart as in the original. But the game no longer stands still between them, and the
party's panel is drawn once a turn instead of twice. The drawing is faster everywhere,
with exactly the same picture: the message window scrolls up about three times as fast,
and working out which squares of the map view the party can see takes a quarter of the
time, so the view redraws faster too. Measured in VICE (not cycle exact), from the key
to the moved view and the next key taken:

| | Original | On the cart |
|---|---|---|
| A step on foot | about 0.26 s | about 0.15 s |
| A step on a horse | about 0.32 s | about 0.16 s |
| The longest wait before a key is noticed | about 0.14 s | about 0.11 s |

The game redraws the map view all the time while it waits for a key, so a key pressed
while it waits is noticed sooner too. Most of what is left of a step is drawing the map
view's tiles.

## Smaller changes from Ultima III Gold

- **"EXIT?" at a town's edge.** Walking off the edge of a town or castle asks first. Only
  Y leaves. This is always on.
- **A default character.** On the surface, keys 1-4 make that party member the active one
  ("<name> ACTIVE"), and 0 clears it ("NO ONE ACTIVE"). While one is active, these
  commands use that character instead of asking "which player?": cast, search a chest,
  torch, join gold, negate time, other command, both gem prompts, steal, transact, unlock
  and ztats. In combat the game always asks. Other prompts still ask as before (healing
  targets, shrines, trading, modify order, fountains and others).
- **DEL deletes in name entry.** In the original, `+` deletes. On the cart DEL does, and
  `+` does not.
- **Buying several daggers.** In the weapon shop, buying daggers asks "AMOUNT-" and buys
  that many at once. Gold's weapon shop is used whole.

## Other changes

- **Keys typed ahead are kept.** The original only ever took the last key waiting in the
  keyboard buffer and threw the rest away, which made it feel unresponsive. The cart
  takes the keys in the order you typed them. This follows the same fix in Ultima IV
  Remastered by Per Olofsson (MagerValp), which the cart's Ultima IV also uses.
- **Joystick in port 2.** Up, down, left and right move (as the keys `@ / : ;`). Fire is
  E (Enter) on Sosaria, T (Transact) in a town, and A (Attack) in combat and on Ambrosia.
- **The gem's view in colour.** Peering at a gem on the surface shows the whole map of
  Sosaria (or Ambrosia) in colour: water blue, grass and forest green, mountains orange,
  towns white, castles yellow, dungeons black, lava red, the moongate cyan. The party's
  square blinks. The map has the same size and position as in the original. While the
  map is up, the rest of the screen is blue, and it comes back when you press a key. In a
  dungeon the peer shows the same symbols as the original, with each square's colour
  showing its kind (walls, doors, secret doors, ladders and others; which colour is
  which kind is inferred from how often each appears in the level maps).

## The page's options for Ultima III

Every option is off on a new cart, so the game plays as it always did. The cart
remembers each setting.

| Key | Option | When it is off |
|---|---|---|
| F | Food used while walking | no food is used up as turns pass |
| P | Turn passes when idle | no turn passes while you wait at the keyboard (on the surface, in towns, in combat, in dungeons) |
| U | Torches used up when lit | lighting a torch does not use it up |
| M | Magic and items used up | from Ultima III Gold's trainers: every class can cast both kinds of magic, with no MP needed or used; doors unlock without a key; peering needs no gem (surface and dungeon); negating time needs no powder |
| A | Attacks can't be avoided | "AVOID?" is asked when a monster steps onto the party (on the surface, in towns and on Ambrosia) or a dungeon encounter starts. Y avoids the fight. The monster stays where it is and asks again at its next step. This idea follows the cheat of the same name in Ultima IV Remastered by Per Olofsson (MagerValp). The question uses the code of Gold's "EXIT?" |
| X | Gold's trainer keys | when on: Ultima III Gold's "ingame keys", see below |

**Gold's trainer keys (X on):**

- **B** (Board) with nothing to board asks S(hip) or H(orse) and gives you one.
- **F7** on the surface asks for X and Y (0-63) and moves the party there.
- **X** in combat ends the fight: "VICTORY!", with the chest.
- **O**(ther command), then the word **AMBROSIA**, takes the party to Ambrosia as the
  whirlpool does. The game recognises words only by their length and last letter, so any
  8-letter word ending in A does the same, as in Gold.

The cart differs from Gold in three ways. A word that does nothing still says "NO
EFFECT!" (in Gold it said "FAILED!"). The teleport refuses coordinates of 64 and above
(Gold accepted up to 99, which put the party off the map). And the keys leave the map
of Sosaria as it is:

- AMBROSIA said on land: the party comes back on foot where it left. In Gold the
  square turned to water and the party came back on a frigate there; said on a castle
  or a town (where the party stands after leaving it), the castle or town was gone.
- B with S or H: the square under the party keeps its tile. In Gold it became water
  (S) or grass (H), a castle or town included.
- X-it from a frigate that is not on water (B, the teleport, AMBROSIA put one
  anywhere) leaves the frigate behind; X-it from a horse on water does the same with
  the horse. In Gold the frigate was parked on the grass, and boarding it again left
  water there.

Through the whirlpool itself, and with crafts where the game puts them, nothing
changes.

## Journey Onward

**J** on the page, offered when there is a saved game, skips the intro (it is cut right
after its screen set-up), the demo and the title menu, and goes straight into the saved
game. Launching with L plays everything as the original does.

## Export and import

- **(D)isks**: the saved game is written to, or read from, a copy of your Scenario disk:
  the Ultima Trilogy's "PLAYER MASTER" or the 1984 edition's "ULTIMA III-SCEN.". The
  cart recognises the disk by its name and asks for it by the name "Scenario". The five
  save units are written to the same sectors the game uses. An exported game plays in
  the original game too.
- **(F)ile**: one file, `ULTIMA III SAVE` (25 blocks), on any disk. Only this cart reads
  it.

An import checks everything it reads before it changes the cart. A wrong disk, a bad file
or RUN/STOP leaves your saved game as it was.

## Known limitations

- Because only Q saves, progress since the last Q is lost at power-off (see Saving).
- Gold's other features are not on the cart: its fastloader and packing (the cart
  replaces all disk access), its remaining trainers (unlimited food and torches are
  covered by the cart's own F and U options), its keyboard remapping for non-US KERNALs,
  and its title and trainer menu.
