# Ultima I on the cart -- what is different

Ultima I is (c) Origin Systems / Lord British. The cart runs the original C64 game. Its
disk access is replaced by flash reads and writes, and four options are added. Unless a
change is listed here, the game plays as the original does. The cart version of Ultima I
runs on real hardware.

## The disk you need

The build reads one disk image that you supply: **the Ultima I disk**. It finds it by
content, under any file name. Everything the game loads comes from it.

Your copy does not have to be unplayed. The build takes only the game's program and data
files from it. The save files (the roster and the four characters) are not copied: the
cart starts with an empty roster and no characters, as a fresh disk would. If your disk
holds a saved game, the build can put it into the cart for you (`make import`),
or you can import it from the page later (below).

## No disk, no waiting

- **No drive questions.** The original asks at start-up which type of disk drive you use.
  The cart skips the question; there is no drive.
- **Loads come from flash.** The original already shipped its own fast loader, so the
  raw transfer rate is about the same (the cart reads about 8.5 KB/s, with the screen on).
  What goes away is the drive's spin-up and seeking. Most of the game's files are stored
  compressed and unpacked as they arrive.
- **The copy protection is harmless.** On an original disk, one file the game asks for
  sits on a deliberately unreadable track, and the game carries on without it. On the
  cart that file is likewise "not there", so the game behaves as on an original disk.

## Faster steps

Outdoors, the view is drawn again only where it changed, and the message window scrolls
in one pass. What you see is the same as in the original. Measured in VICE (not cycle
exact):

| | Original | On the cart |
|---|---|---|
| A step, from the key to the moved view | about 0.16 s | about 0.10 s |
| A key pressed while you wait, until it is taken | up to about 0.12 s | up to about 0.04-0.08 s |

Holding a direction key walks at the same pace as before: the game's own key repeat
sets it (about a quarter of a second a step). Tapping is faster. The water, the flags
and the monsters move at the original pace, kept by a clock rather than by the drawing,
and idle turns (option P on) still pass about every 15 seconds, as in the original.

## Saving

- **The game saves as it always did**: a character with **Q**, the roster from the
  character menu. Each of the four characters is its own saved game, as on the disk.
- **A save survives a power cut.** Each save is written twice: first to a spare area,
  then over the old save. If the power fails during a save, you get either the old save
  or the new one, complete. If the power went while the old save was being overwritten,
  the cart finishes the job the next time it is switched on, before anything else starts.
- A save takes a second or two.

## The game's page

The page lists the characters in the roster, each with its hit points and food. A
character in the roster whose own save is missing shows "(no data)".

**Journey Onward is not offered for Ultima I.** The game has four characters and asks
which one to play, so there is no single saved game to go straight into. Launch with
**L** and pick the character as usual.

**Reset (R)** empties the roster and removes all four characters, after asking. The
launcher's own settings are kept.

## The page's options for Ultima I

On a new cart every option is as the game always was (F, P and S on, X off). The cart
remembers each setting.

| Key | Option | When it is off / on |
|---|---|---|
| F | Food used while walking | Off: moving uses no food. Other food losses are unchanged (the gremlins still eat half of it) |
| P | Turn passes when idle | On: a turn passes when you leave the keyboard alone (outdoors after 15 seconds, as in the original). Off: no turn passes while you wait at the keyboard: outdoors, in dungeons, in towns and in castles |
| S | NPCs can steal items | Off: Iolo the bard in the towns and the jester in the castles no longer take your weapons when you stand in their way, and a thief in a dungeon hits you instead of stealing a weapon. The gremlins still eat half your food, and a gelatinous cube still destroys your armour |
| X | Locate, teleport, vehicle | On: outdoors, **F1** shows where you are (`Position land-0 X-30 Y-31`, no turn passes), **F7** asks for `land-`, `X-` and `Y-` and moves you there: a land 0-3 (0 the lands of Lord British, 1 the Feudal Lords, 2 the Dark Unknown, 3 Danger and Despair), then two digits each, 00-63. **B**(oard) where there is nothing to board offers **(H)orse, (C)art, (R)aft, (F)rigate, (A)ircar**, and you are in it. Anything else, or with the option off, is "Huh?" and "nothing to Board!" as before |

The other options (U, M, A, V, W, G) belong to other games and are not offered for
Ultima I.

The X option follows the trainer keys of "Ultima III Gold" (cracked, trained and enhanced
by MagerValp), as the cart's Ultima II has them. The squares of each land, and where
every town, castle, landmark and dungeon is, are in the maps `make maps` draws from your
disk (`build/maps/u1/`, `places.txt`). F1 gives the same numbers for where you stand;
out at sea beyond a land's edge they run from -10 to 73. A teleport does not look at the square it lands
on: with a raft or a frigate on land you can only teleport again or X-it (which works on
water, grass and forest). No shuttle and no time machine are offered: boarding one
launches it at once, and the time machine needs the four gems.

## Export and import

With **E** and **I** on the page, the saved game goes to a real disk and back, in drive
8, 9, 10 or 11.

- **(D)isks**: a copy of your Ultima I disk. The cart writes the roster and each
  character as the game itself does (the old file scratched, then saved), so an exported
  game plays in the original game too. A character that does not exist on the cart is
  not written; one that is missing on the disk is removed from the cart by an import, as
  the original would have no character there either.
- **(F)ile**: one file, `ULTIMA I SAVE` (about 6 blocks), on any disk. Only this
  collection reads it. It is a good backup before flashing a full cart image.

An import checks everything it reads before it changes the cart. A wrong disk, a bad file
or RUN/STOP leaves your saved game as it was.

The save editor (`ultima-save-editor.html`) reads and writes Ultima I's roster and
characters: from an exported file, from a copy of the Ultima I disk, or from the cart
image itself when you play in an emulator.

## Known limitations

- **Do not press RESTORE while Ultima I is loading.** The game itself ignores RESTORE,
  and so does the cart between loads. During a load, though, the memory the C64 jumps
  through on RESTORE is not set up: the cart's Ultima II and III guard against that,
  Ultima I's driver has no room for the guard.
